Long context (32k)

Two stages: a retrieve-then-decide wrapper that keeps single-pass latency today, and a hierarchical stage-B aggregator that attends over all 32k tokens with no data loss.

Retrieve-then-decide

src/laya_longctx.py keeps the single-pass ~32ms behaviour on long inputs: chunk the state, TF-IDF-rank chunks against the question text, and run Router.predict on the top-k chunks only. Inputs that already fit (about 900 tokens) skip retrieval entirely.

from laya_longctx import LongContextRouter
from laya import Router

r = LongContextRouter(Router())          # or LongContextRouter(device="cuda")
res = r.predict(long_state, questions)   # top_k=3, chunk_words=120, overlap=20
res["longctx"]  # {"retrieved": True/False, "chunks": N, "kept": [...], ...}

Stage-B aggregator

Retrieval drops chunks by design. laya-train/hier.py is the no-data-loss stage B: chunk embeddings come from the frozen Laya encoder (mean-pooled, offline-precomputable) and a small trainable Transformer attends over all of them.

SymbolValue
CHUNK_TOKENS256
MAX_CHUNKS128 → 32,768 tokens effective context
Aggregator(d_model=1024, n_layers=4, n_heads=8, dropout=0.1)~25M trainable params, trains in minutes
agg = Aggregator()                       # d_model=1024, 4 layers, 8 heads
pooled = agg(chunks, mask)               # (B, C, D) -> (B, D), masked mean
logits = agg.decide(pooled, options, qtype="choice")  # per-option energies
logits = agg.decide(pooled, None, qtype="noul")       # (B, 2) true/false

Architecture

32k tokens → 128 × 256-token chunks → frozen Laya encoder (mean-pool) → 128 chunk vectors → 4-layer aggregator Transformer → per-qtype heads (choice_head / score_head energy per option, noul_head true/false logits). Full O(n²) attention over 32k tokens would be ~4B entries per layer — untrainable on a T4; this design trains the ~25M-parameter core over 128-token sequences instead. Stage-B data (long concatenations + typed-decisions long states) is built by long_data.py.
