Primitives: Choice, Score, Noul

Three typed questions cover classification, ordinal rating, and boolean judgement — all answered in parallel in a single pass.

State

state is whatever the decision depends on: a plain string, a JSON dict, or a list of conversation turns. The encoder renders each question against the same state with marker tokens that locate every option; sequences are truncated to the checkpoint window (max_len 512, question head budget head_max_len 192).

Choice

{"type": "choice", "instructions": "Which section does this article belong to?",
 "criteria": {"world": "international news", "sports": "matches and athletes",
              "business": "markets and companies", "tech": "science and technology"}}

Returns probabilities over the named options. criteria may be a dict of label: description or a plain list of labels. Use it for intent, topic, triage — anything with a fixed label set.

More options than the head budget?

When a label set is huge (e.g. Banking77’s 77 intents), use the shortlist coarse-to-fine pattern: rank options with embeddings, then decide over the top-k.

Score

{"type": "score", "instructions": "Rate satisfaction from this review.",
 "criteria": ["1", "2", "3", "4", "5"]}

Ordinal rating over ordered levels. Returns probabilities per level; take the argmax or an expectation depending on your downstream math.

Noul

{"type": "noul", "instructions": "This message is a phishing attempt."}

Boolean judgement with no criteria. Returns noul in [0, 1] — the probability the statement is true of the state. Threshold at 0.5 for a hard decision.

Parallel single-pass

Agent.system_one(state, questions) evaluates every question in one encoder forward pass: one tokenised sequence per question, marker positions per option, a single batched call. Mixing types is free — the quickstart’s choice + score + noul costs one pass, and the typed-decisions benchmark leans on exactly this.

Confidence

Probabilities are post-calibrated per question type (temperature scaling fit on held-out items, see fit_one_temp in the training recipe), so reported confidence tracks empirical accuracy. Calibration quality is measured as ECE; the Jev target is 0.246. Calibrated confidence is what makes confidence-gated routing work: low confidence means “ask for more evidence”, not a silent wrong answer.
